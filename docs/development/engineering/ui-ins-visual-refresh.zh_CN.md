# ins 风 UI/UX 改版策划

状态：**配色与控件改动已落地，待真机验证**。下文的 token 替换与控件审查现已进入
正式主题（[`ui_theme.c`](../../../main/ui/ui_theme.c)）。对比度仍需在真实 RGB565
屏上复核，文末的待定问题仍然开放。

## 已实现

- [`ui_theme.c`](../../../main/ui/ui_theme.c) 的两套配色已换成下表的暖调中性色，
  藏青底 + 电光青的方案已移除。
- `ui_row_create()` 的选中指示改为行自身 3px 左边框，不再建独立子对象；`ui_row_t`
  直接保存标题标签句柄，不再依赖子对象下标。
- 赛事中心"战队"页新增胜率横条，由块元素字形（`█`/`░`）拼成，每行不增加任何
  LVGL 对象。

## 范围

本策划覆盖 `main/ui/` 下 Passport 随身工具箱应用的视觉语言。颜色与字号已经只有
一个来源——[`ui_theme.c`](../../../main/ui/ui_theme.c)——因此改版基本等同于替换
配色 token 加一次控件审查。导航、页面结构、数据模型与按键行为不在范围内。

## 现在的主题为什么"AI 味重"

[`ui_theme.c`](../../../main/ui/ui_theme.c) 里的配色本身是自洽的，但正落在机器
生成仪表盘的默认观感上：

- 深色主题把近黑的藏青底（`0x0B0E13`）、蓝灰面板（`0x151A22`、`0x1F2833`）和
  电光青强调色（`0x22D3EE`）配在一起。青配藏青是"AI 产品"最高频的视觉签名。
- 多个语义色饱和度很高（`live 0xFF4757`、`ok 0x34D399`、`soon 0xFFB020`），
  看起来像一排状态灯，而不是克制的编辑风界面。
- 浅色主题的强调色（`0x0891B2`）延续了同一个冷蓝色系。

已经做对、应当保留的部分：不用渐变、不用投影，层级靠 1px 描边、2px 语义色条和
表面明度差表达。改版只换配色的情绪，并微调几处控件细节。

## 目标取向

这里的"ins 风"指**编辑式极简**，不是照抄任何产品：

- 用暖调中性纸色（米白 / 暖炭黑）取代蓝灰。
- 只保留一个低饱和强调色，其余全是灰阶。
- 用充足留白与少量圆角（4 / 6 / 8）取代视觉噪音。
- 层级只用间距、不透明度与 1px 细线表达，绝不用渐变或发光。

### 禁止项

- 任何渐变（现在的代码没有，继续保持）。
- 蓝紫色系，以及大致落在 200°–280° 的青到紫区间的强调色。
- 同一时刻使用一个以上强调色相。
- 高饱和的横幅填充；横幅改为中性面板加一条强调色边。

## 配色

只改 `PALETTE_DARK` 与 `PALETTE_LIGHT`。所有页面继续调用既有的 `ui_c_*()` 访问器，
因此不需要改动任何页面代码。

下表数值已在 [`ui_theme.c`](../../../main/ui/ui_theme.c) 落地。对比度——尤其是
`card` 上的 `dim` 文本与 `card` 上的 `accent`——仍需逐屏在真实 RGB565 屏上确认。

| Token | 角色 | 深色方案 | 浅色方案 |
| --- | --- | --- | --- |
| `bg` | 页面背景 | `0x100E0C` | `0xF7F4F0` |
| `card` | 卡片 / 列表行 | `0x1B1815` | `0xFFFFFF` |
| `panel` | 嵌套容器 | `0x25201B` | `0xEFEAE3` |
| `text` | 主文本 | `0xF3EEE8` | `0x1B1714` |
| `dim` | 次级文本 | `0xA79E95` | `0x6E655C` |
| `accent` | 唯一强调色 | `0xE08B5A` | `0xC0623A` |
| `live` | 进行中 / 直播 | `0xE2604A` | `0xB93A2A` |
| `soon` | 即将开始 | `0xD6A24C` | `0x9A6B1E` |
| `done` | 已结束 | `0x6F6862` | `0xA69E95` |
| `ok` | 成功 / 在线 | `0x7FA37A` | `0x567B50` |
| `warn` | 警告 / 未校准 | `0xD98E3F` | `0x9A6B1E` |
| `sel` | 选中行背景 | `0x2A231E` | `0xE9E2D9` |
| `border` | 1px 分隔线 | `0x2E2822` | `0xDDD5CB` |

设计理由：强调色选了暖调赤陶/琥珀，与保留的 `live` 红、`warn` 琥珀刻意拉开距离，
这样"进行中/警告"的语义不会和强调色混在一起。

## 字体

- 保留 `app_font_12/16/20`（中文）与 Montserrat 32/40（仅数字），不新增字体资源。
- 不引入中文粗体/中等字重；生成字体只有单一字重。层级改用字号、颜色与间距表达。
- 展示级数字"仅 ASCII"的规则不变：它既省 Flash，又避免为几个数字带一整套中文字形。

## 控件

| 控件 | 改动 |
| --- | --- |
| 卡片（`ui_card_create`） | 保留 1px 描边与 8px 圆角。左侧色条由 3px 收到 2px，并只在状态强调时使用，不做纯装饰。 |
| 列表行（`ui_row_create`） | 保留 40px 行高与 6px 圆角。选中强调改由 `sel` 填充表达；左侧指示条仅在选中时显示。 |
| 标签页（`ui_tabs_create`） | 保留 2px 下划线，改用 `accent` 着色。 |
| 横幅（`ui_banner_create`） | 不再用高饱和语义色整块填充。改为 `panel` 底色 + 3px `accent`（或对应语义色）左边缘，文字用 `text`。 |
| 空状态（`ui_empty_create`） | 增加纵向留白，文案不变。 |
| 状态栏 | 保持单色，仅 LIVE 角标可用 `live`。 |

## 动效

不新增动画。页面构建与重建一律维持 `LV_ANIM_OFF`；屏幕是单 DMA 缓冲、无 PSRAM，
大面积重绘是帧预算的主要风险。参见
[仪表界面平滑与布局](../../reference/y2lin/meter-ui-smoothing-and-layout.md)。

## 迁移步骤

1. 改 [`ui_theme.c`](../../../main/ui/ui_theme.c) 里的两套配色。
2. 审查剩余硬编码颜色。应当只留下纯黑遮罩（`ui_home.c`、`ui_settings.c`、
   `ui_timeedit.c`、`ui_theme.c`）与二维码画布的黑白调色板（`ui_identity.c`），
   其余一律走 `ui_c_*()`。
3. 逐屏在设备上验证对比度，并用
   [串口截图协议](../../reference/y2lin/serial-screenshot-protocol.md)留证。
4. 对照品牌参考确认一致性：[品牌与产品](../../brand/brand-and-product.md)。

## 待定问题

- **强调色相。** 当前提案是赤陶/琥珀。备选是鼠尾草绿或纯灰阶；纯灰阶会迫使重新
  设计 `live`/`ok`/`warn` 这几个语义色。
- **浅色主题的定位。** 提案沿用暖米白。设备默认主题是否继续用深色（现状）属于产品决策。
- **改动范围。** 只换 token，还是同时重排个别页面（主页宫格、240×320 密度）？提案
  假设第一轮只换 token。
- **对比度目标。** 透射式 LCD 加背光下，要求多高的最低对比度——严格对齐 WCAG AA，
  还是采用手调的经验目标。
